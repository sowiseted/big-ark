## 터미널과 경로

**아래 명령은 PowerShell 에서도 WSL 터미널에서도 같다.** `docker` · `git` · `ssh` · `ssh-keygen` 은 두 곳에서 이름이 같다.

한 가지만 다르다 — **작업 폴더 경로 표기**다.

| 터미널 | 지난주 폴더로 가는 법 |
|---|---|
| PowerShell | `cd d:\dev\big-ark` |
| WSL | `cd /mnt/d/dev/big-ark` |

`D:` 가 아닌 곳에 만들었으면 자기 경로로 바꾼다. **한 번 확인해 두면 12주 내내 쓴다.**

## 파일 이름 하나 — `compose.yml` 과 `docker-compose.yml`

**둘은 같은 것이다.** 앞엣것이 지금 이름이고 뒤엣것이 옛 이름이다.

| | 지금 | 예전 |
|---|---|---|
| 파일 이름 | `compose.yml` | `docker-compose.yml` |
| 명령 | `docker compose up` (띄어쓰기) | `docker-compose up` (붙임표) |

**검색하면 옛 이름이 훨씬 많이 나온다.** 실무 저장소에도 아직 `docker-compose.yml` 이 대부분이다 — 이름을 바꿀 이유가 없어서 그대로 두는 것이지 낡아서 안 도는 것이 아니다. **둘 다 읽을 줄 알면 된다.** 이 수업에서는 새 이름으로 쓴다.

# P1. 선언 — 명령으로 한 번, 파일로 한 번 — 20분

**같은 것을 두 방식으로 해 본다.** 이 과제는 그것이 전부다.

---

### ① 먼저 명령으로 띄운다 — 3분

한 줄로 친다. 길다. **한 글자도 이해하지 않아도 된다.** 지금은 그냥 친다.

```bash
docker run -d --name lab-db -p 5432:5432 -e POSTGRES_PASSWORD=labpass ____________
```

맨 뒤 빈칸에는 **공유 폴더에서 올린 이미지의 이름과 태그**를 넣는다 (`docker images` 로 확인한 그 값).

```bash
docker ps
```

`lab-db` 가 `Up` 으로 보이면 됐다.

### ② 지운다 — 그리고 어디에 남았는지 본다 — 1분

```bash
docker rm -f lab-db
docker ps -a
```

목록에서 사라졌다. **방금 친 명령은 지금 어디에 남아 있는가?**

셸 히스토리 한 줄뿐이다. 다음 주에 다른 자리에 앉으면 그것도 없다. **오늘 이 자리에서 되던 것이 다음 주에 되지 않는 이유가 여기 있다.**

---

### ③ 같은 것을 파일로 쓴다 — 7분 ★오늘의 중심

**방금 친 명령의 각 조각이 파일의 어느 자리로 가는지 먼저 본다.**

```
docker run -d --name lab-db -p 5432:5432 -e POSTGRES_PASSWORD=labpass  이미지:태그
            │       │            │                  │                      │
            │       │            │                  │                      └─ image:
            │       │            │                  └──────────────────────── environment:
            │       │            └─────────────────────────────────────────── ports:
            │       └──────────────────────────────────────────────────────── container_name:
            └──────────────────────────────────────────────────────────────── (없음 — 파일은 원래 배경에서 띄운다)
```

| 명령의 이 부분 | 파일의 이 키 | 뜻 |
|---|---|---|
| `-d` | **없다** | 파일로 띄우면 기본이 배경이다 |
| `--name lab-db` | `container_name:` | 컨테이너에 붙는 이름 |
| `-p 5432:5432` | `ports:` | `호스트포트:컨테이너포트` |
| `-e KEY=VALUE` | `environment:` | 컨테이너 안의 환경 변수 |
| `이미지:태그` | `image:` | 무엇을 띄울 것인가 |
| — | **`db:`** ← **새로 생긴다** | **서비스 이름** |

★ **명령에 없던 것이 파일에 하나 생긴다 — 서비스 이름이다.** 명령은 한 번에 하나만 띄우지만 파일은 여럿을 함께 적기 때문에, 각각을 부를 이름이 필요하다. **다음 주에 이 아래로 한 덩어리가 더 붙는다.**

**이제 `week02/compose.yml` 을 만든다.** 아래를 보고 빈칸을 채운다.

```yaml
services:                                    # 매핑 — 아래가 서비스 목록이다
  db:                                        # 서비스 이름 (자유) — 명령에는 없던 것
    image: ____________________              # 공유 폴더에서 올린 이미지:태그
    container_name: lab-db                   # --name 과 같다
    ports:                                   # 시퀀스 — 앞에 - 가 붙는다
      - "5432:5432"                          # ★ 따옴표를 친다. 이유는 ⑤
    environment:                             # 매핑 — 아래는 key: value
      POSTGRES_PASSWORD: labpass             # ⑥ 에서 이 줄을 고친다
```

**이 파일에 세 자료형이 다 들어 있다.**

| 자료형 | 이 파일에서 | 생김새 |
|---|---|---|
| **매핑** | `services:` · `db:` · `environment:` | `이름: 값` — 이름으로 찾는다 |
| **시퀀스** | `ports:` 아래 | `- 값` — 순서로 찾는다 |
| **스칼라** | `lab-db` · `"5432:5432"` | 더 안 쪼개지는 값 하나 |

> **긴 구성 파일도 이 셋의 조합이다.** 100줄짜리를 만나도 새로 배울 것은 없다.

---

### ④ 파일로 띄운다 — 그리고 한 번 더 — 2분

```bash
docker compose up -d
docker ps
```

`lab-db` 가 다시 떴다. **명령을 다시 치지 않았다.**

**한 번 더 친다.**

```bash
docker compose up -d
```

이번에는 아무 일도 일어나지 않는다. `Running` 이라고만 나온다. **이미 그 상태이기 때문이다.**

> **이것이 「멱등」이다.** 몇 번을 돌려도 결과가 같다. 명령형은 두 번 하면 두 개가 생기고, 선언형은 두 번 해도 하나다. **자동화가 선언형을 고르는 이유가 이것 하나다** — 실패했을 때 그냥 다시 돌리면 되기 때문이다.

### ⑤ 일부러 틀려 본다 — 4분

**세 가지를 차례로 저지르고 고친다.** 오늘 여기서 밟아 두면 다음에는 에러 메시지만 보고 안다.

**틀림 1 — 탭으로 들여쓴다**

`ports:` 아래 줄의 들여쓰기를 지우고 **탭 키**로 다시 넣는다.

```bash
docker compose up -d
```

거부당한다. **YAML 은 탭을 들여쓰기로 인정하지 않는다.** 눈으로는 공백과 구분이 안 되는데 파서는 구분한다. 편집기에서 공백으로 되돌린다.

**틀림 2 — 들여쓰기 깊이를 어긋나게 한다**

`container_name:` 을 `image:` 보다 두 칸 더 들여쓴다.

```bash
docker compose config
```

`docker compose config` 는 **파일이 어떻게 읽혔는지 펴서 보여준다.** 지금 `container_name` 이 `image` 의 값 안으로 들어갔거나 오류가 난다. **들여쓰기가 곧 소속이다.** 원래대로 돌린다.

**틀림 3 — 따옴표를 뗀다** ★ 이건 안 틀릴 수도 있다

`"5432:5432"` 에서 따옴표를 뗀다. 그대로 뜰 수도 있다.

**그런데도 따옴표를 치는 이유는 판본마다 다르게 읽히기 때문이다.** 아래 값들은 파서에 따라 갈린다.

| 이렇게 쓰면 | 이렇게 읽힐 수 있다 |
|---|---|
| `no` · `off` · `yes` · `on` | 참·거짓 (문자열이 아니라) |
| `5432:5432` | 시각처럼 계산된 숫자 하나 |
| `08` | 오류 (8진수로 읽다가) |
| `1.10` | `1.1` (뒤 0 이 사라진다) |

> **오늘 되던 것이 다른 PC 에서 안 되는 부류의 문제다.** 값에 `:` · `#` · 앞자리 `0` 이 들어가거나, 값이 `yes`/`no` 처럼 생겼으면 **따옴표를 친다.** 따옴표를 친 것은 언제나 문자열이다.

```bash
docker compose config      # 고친 뒤 다시 확인
```

### ⑥ 비밀번호를 파일 밖으로 뺀다 — 2분

지금 `compose.yml` 에 비밀번호가 그대로 적혀 있다. **이 파일은 곧 커밋된다.**

`compose.yml` 의 그 줄을 고친다.

```yaml
    environment:
      POSTGRES_PASSWORD: ${DB_PASSWORD}      # 값이 아니라 이름만 남긴다
```

같은 폴더에 **`.env`** 를 만든다.

```
DB_PASSWORD=labpass
```

> ★ **값 뒤에 공백을 넣지 않는다.** `labpass ` 처럼 뒤에 공백이 있으면 **그 공백까지 비밀번호가 된다.** 파일은 멀쩡해 보이는데 접속만 안 되고, 눈으로는 절대 안 보인다.

같은 폴더에 **`.gitignore`** 를 만든다.

```
.env
```

```bash
docker compose down
docker compose up -d
docker compose config      # 비밀번호가 채워져 읽히는지 확인
```

> **이것은 보안 상식이 아니라 선언의 문제다.** 「무엇을 저장소에 남길 것인가」를 가르는 첫 판단이며, 오늘 P3 에서 개인키를 두고 같은 판단을 한 번 더 한다.

# P2. 기록 — 문서 세 층과 첫 결정 — 25분

**이 회차 실습의 중심이다.**

### ① 세 자리를 만든다 — 5분

지난주에 만든 그릇 안에 **무엇을 어디에 쓰는지**를 정한다.

```bash
cd d:\dev\big-ark
mkdir docs
cd docs
mkdir 결정
mkdir 구조
mkdir 절차
```

| 층 | 무엇을 담는가 | 반감기 |
|---|---|---|
| **결정** | **왜** 그렇게 했는가 | 길다 — 조건이 바뀌기 전까지 참이다 |
| **구조** | **무엇이 어디에** 있는가 | 중간 — 옮기면 거짓이 된다 |
| **절차** | **어떻게** 하는가 | 짧다 — 도구 판이 올라가면 거짓이 된다 |

> **셋을 섞어 놓으면 전부 절차의 반감기를 따라간다.** 한 문서 안에 절차가 섞여 있으면 절차가 낡는 순간 그 문서 전체를 믿을 수 없게 된다. **갈라 두는 것이 문서를 오래 살리는 유일한 방법이다.**

### ② 결정 기록 1건을 쓴다 — 12분 ★검수 대상

**소재는 오늘 P1 에서 내린 판단이다 — 이미지 태그를 어떻게 적었는가.**

`결정기록_양식.md` 를 `docs/결정/` 아래에 복사해 채운다. 파일 이름은 자기 규약대로 정한다.

**네 칸이다 — 배경 · 결정 · 근거 · 영향.** 그리고 **「무엇을 포기했는가」가 검수 대상이다.**

> 태그를 고정하면 다음 주에도 같은 것이 뜨지만 그 사이 나온 수정은 못 받는다. 고정하지 않으면 반대다. **어느 쪽을 골랐든 반대쪽을 포기한 것이며, 그 포기가 적혀 있어야 결정 기록이다.**

### ③ 인덱스 1장 — 5분

`docs/` 바로 아래에 인덱스를 한 장 만든다. **무엇이 정본인지 가리키는 것이 전부다.**

```markdown
# 문서 인덱스

| 문서 | 무엇인가 | 상태 |
|---|---|---|
| 결정/(파일명) | 이미지 태그 표기 결정 | 유효 |
```

> **파일이 있다는 것이 정본이라는 뜻은 아니다.** 폐기된 문서도 파일로는 남는다. 무엇이 유효한지는 **인덱스만 안다.**

### ④ 커밋한다 — 3분

```bash
git add .
git commit -m "week02: 문서 세 층과 첫 결정 기록"
```

### 완료 판정

**결정 기록에 「그때 무엇을 포기했는가」가 적혀 있다.**

> **문서는 3장을 넘기지 않는다.** 무엇을 버릴지가 이 과제의 절반이다.
> 남길 것 — 되돌릴 수 없는 결정 · 두 번 물어본 것 · 다음 사람이 알 수 없는 것

# P3. 접속 — 키 하나를 두 곳에 등록한다 — 25분

### ① 비밀번호로 한 번 들어간다 — 3분

```bash
ssh ____________@____________________
```

들어가졌으면 바로 나온다.

```bash
exit
```

> **되긴 된다.** 그런데 이 방식은 자동화가 못 쓴다. 사람이 앉아서 쳐야 하기 때문이다. **자동으로 도는 것은 전부 이 지점에서 막힌다.**

### ② 키 쌍을 만든다 — 4분

```bash
ssh-keygen -t ed25519 -C "본인메일@example.com"
```

- 저장 위치를 물으면 **엔터** (기본값)
- 암호를 물으면 **엔터 두 번** (실습이므로 비워 둔다)

```bash
ls ~/.ssh
```

두 개가 생겼다.

| 파일 | 무엇인가 | 어디로 가는가 |
|---|---|---|
| `id_ed25519` | **개인키** | **어디에도 안 보낸다** |
| `id_ed25519.pub` | **공개키** | 접속하고 싶은 곳마다 등록한다 |

★ **`.pub` 이 붙은 쪽만 밖으로 나간다.** 헷갈려서 개인키를 올리면 키를 새로 만들어야 한다.

### ③ 공개키를 학과 서버에 등록한다 — 5분

```bash
ssh-copy-id ____________@____________________
```

`ssh-copy-id` 가 없으면 공개키 내용을 직접 붙여 넣는다.

```bash
cat ~/.ssh/id_ed25519.pub
```

이 한 줄을 복사해서, 서버에 비밀번호로 들어간 뒤 `~/.ssh/authorized_keys` 끝에 붙인다.

```bash
ssh ____________@____________________
```

**비밀번호를 묻지 않으면 됐다.**

### ④ 별명을 만든다 — 4분

`~/.ssh/config` 파일을 만들거나 연다. 아래를 적는다.

```
Host aisw
    HostName ____________________
    User ____________
    IdentityFile ~/.ssh/id_ed25519
```

```bash
ssh aisw
```

**주소도 계정도 안 쳤다.**

> **편의 기능이 아니다.** 접속 정보가 명령이 아니라 **설정에 사는 것**이며, P1 에서 비밀번호를 `.env` 로 뺀 것과 같은 축이다. 서버가 바뀌면 고칠 자리가 한 곳이다.

### ⑤ 같은 공개키를 저장소 호스팅에 등록한다 — 7분 ★

**절차가 ③ 과 같다.** 화면만 다르다.

1. GitHub → Settings → **SSH and GPG keys** → New SSH key
2. `cat ~/.ssh/id_ed25519.pub` 의 **같은 한 줄**을 붙여 넣는다

지난주에 원격을 안 걸었으면

```bash
cd d:\dev\big-ark
git remote add origin git@github.com:<본인계정>/big-ark.git
git branch -M main
git push -u origin main
```

지난주에 `https://` 로 걸었으면 주소만 바꾼다.

```bash
git remote set-url origin git@github.com:<본인계정>/big-ark.git
git push -u origin main
```

★ **같은 키가 두 곳에서 통했다.** 키 인증은 **특정 서버의 기능이 아니라 방식**이다.

### ⑥ (선택) 포트 포워딩 한 번 — 시간이 남으면

```bash
ssh -L 8080:localhost:____ aisw
```

이 상태에서 브라우저로 `localhost:8080` 을 연다. **서버 쪽 화면이 내 브라우저에 뜬다.**

> **관리 화면을 인터넷에 열지 않고 보는 방법이다.** 터미널을 닫으면 통로도 닫힌다.

### 완료 판정

**`ssh aisw` 로 비밀번호 없이 들어가고, 오늘 산출물이 원격에 올라갔다.**

> **개인키는 저장소에 넣지 않는다.** P1 ⑥ 의 `.env` 와 같은 판단이다.
> **그리고 실습실 PC 는 내 것이 아니다.** 오늘 만든 개인키가 이 PC 에 남는다는 사실을 결정 기록에 한 줄 적어 둘 값이 있다.

## 막혔을 때 — 순서대로 확인한다

### 1. `docker compose` 가 파일을 못 찾는다

```bash
ls
```

**지금 폴더에 `compose.yml` 이 있는가.** `week02` 안에 있는지 확인한다.

### 2. 파일은 있는데 읽다가 거부당한다

```bash
docker compose config
```

**이 명령이 어디가 문제인지 줄 번호로 알려준다.** 위에서부터 셋을 본다 — **탭이 들어갔는가 · 들여쓰기 깊이가 맞는가 · `:` 뒤에 공백이 있는가.**

> `key:value` 는 안 된다. **`key: value` 로 공백이 하나 필요하다.**

### 3. 포트가 이미 쓰이고 있다

```bash
docker ps -a
```

**지난주 컨테이너나 아까 ① 의 `lab-db` 가 남아 있는 경우가 대부분이다.**

```bash
docker rm -f lab-db
```

그래도 안 되면 `compose.yml` 의 앞 포트만 바꾼다 — `"15432:5432"`. **앞이 내 PC, 뒤가 컨테이너 안이다.** 이때 P4 의 접속 포트도 같이 바뀐다.

### 4. `.env` 를 만들었는데 값이 안 들어간다

```bash
docker compose config
```

`${DB_PASSWORD}` 가 그대로 보이면 **`.env` 가 `compose.yml` 과 같은 폴더에 없다.**
값이 이상하게 들어갔으면 **`.env` 값 뒤 공백**을 본다.

### 5. 키를 등록했는데 계속 비밀번호를 묻는다

```bash
ssh -v aisw
```

`-v` 를 붙이면 어느 키를 시도하다 어디서 거절당했는지 나온다. 흔한 원인 둘이다.

- **개인키 파일 권한이 느슨하다** → `chmod 600 ~/.ssh/id_ed25519`
- **공개키가 아니라 개인키를 등록했다** → `.pub` 쪽을 다시 등록한다

### 6. `git push` 가 거부당한다

```bash
ssh -T git@github.com
```

이름을 불러 주면 키는 통한 것이다. 그러면 원격 주소를 본다.

```bash
git remote -v
```

`https://` 로 시작하면 아직 옛 주소다 — P3 ⑤ 의 `set-url` 을 다시 한다.
