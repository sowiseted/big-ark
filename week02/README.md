## 이 회차 배포물의 고유 처리 셋 ★

### 1. P1 이 명령어 실행을 앞에 둔다 — 교안과 다르다

**교안 P1 은 「1회차에 명령어로 띄운 컨테이너를 구성 파일로 다시 쓴다」로 되어 있다.** 배포물은 **오늘 그 명령을 먼저 치게 한다**(P1 ①②).

| 이유 | |
|---|---|
| **1** | 1회차에서 친 것은 `docker run hello-world` 한 줄이며 **옵션이 없다.** 옮길 인자가 없으면 명령↔키 대응이 성립하지 않는다 |
| **2** | 교안 P1 의 목표 문장이 **「같은 것을 두 방식으로 해 보는 것」**이다. 1회차 대상(hello-world)과 2회차 대상(DB)이 다르면 「같은 것」이 아니다 |
| **3** | 명령을 친 뒤 **지우고 「그 명령이 지금 어디 남았는가」를 묻는 자리**(P1 ②)가 선언형의 필요를 만든다. 이것이 이 과제의 축이다 |

**시간은 4분이며 P1 20분 안에서 흡수된다.** 교안 개정 대상이므로 §「정본 반영 대기」에 올렸다.

### 2. 볼륨을 쓰지 않는다 — 3회차 통과선을 선점하지 않기 위해

P1 의 구성 파일에 `volumes:` 를 넣지 않는다. **3회차 P1 의 통과선이 「컨테이너를 지웠다 다시 올려도 남는다」**이기 때문이다.

**그래서 P4 ③ 에서 내리면 안에 있던 것이 같이 사라진다.** 그 자리에 "남기려면 무엇이 더 필요한가 — 그 답이 다음 주다"를 한 줄 걸어 두었다. **결손이 아니라 다음 회차로 가는 걸개다.**

### 3. 터미널을 갈라 쓰지 않는다

교안 §1-4 는 **WSL 을 기본 경로**로 두었고, 1회차 배포물은 **PowerShell** 로 쓰여 있다. 3회차 배포물은 `bash` 표기다.

**배포물은 둘 다에서 같은 명령만 쓴다.** `docker` · `git` · `ssh` · `ssh-keygen` · `cat` · `ls` 는 두 터미널에서 이름이 같다. 다른 것은 **작업 폴더 경로 표기 하나뿐**이라 §「터미널과 경로」에 표로 한 번 준다.

> **WSL 을 기본으로 못 박지 않은 이유** — 1회차의 Docker Desktop 설치가 켠 것은 WSL2 **백엔드**이며 리눅스 배포판 설치는 별개다. 배포판이 없는 PC 에서는 WSL 터미널 자체가 없어 **P1 이 시작되지 않는다.** 교안 §1-4 개정 대상이다.
