# 결정 기록 — 이미지 태그를 어떻게 적을 것인가

> **2주차 실습 P2** · 이 파일을 자기 저장소의 **`docs/결정/`** 아래에 복사해 채운다.
> 파일 이름은 오늘 자기가 정한 규약을 따른다.

---

## 왜 이것을 기록하는가

**오늘 P1 에서 이미 결정했기 때문이다.** `compose.yml` 의 `image:` 줄에 태그를 붙였든 안 붙였든, 그것은 **선택이었지 기본값이 아니다.**

문제는 6개월 뒤다. 그때 이 파일을 여는 사람은 — 대개 자기 자신이다 — **왜 그렇게 적었는지 물을 데가 없다.** 커밋 제목에는 무엇을 했는지만 남고 왜 골랐는지는 안 남는다.

**결정 기록은 같은 결정을 두 번 논의하지 않기 위해 쓴다.**

---

무엇을 정해야 했는가. 한 줄이면 된다.

(예: week02/compose.yml 의 image: 줄에 태그를 붙일지 정해야 했다)
```

```

## 4. 무엇을 포기했는가 ★이 칸이 검수 대상이다

고르지 않은 쪽으로 갔으면 **무엇이 좋았을 텐데** 그것을 포기했는가.

```
(예: 태그를 고정하면서, 그 사이 나온 수정을 자동으로 받는 것을 포기했다.
     받으려면 앞으로 사람이 태그를 올려 줘야 한다)
```

**언제 이 결정을 다시 봐야 하는가**

```
(예: 지금 태그가 더 이상 배포되지 않을 때 / 보안 수정을 놓쳤다는 것을 알았을 때)
```

## 5. 영향

이 결정이 다른 무엇을 정하는가. **자기 것에 걸리는 것만 한 줄씩 적는다.**

- **재현** — 다른 PC 에서 같은 파일로 띄웠을 때 같은 것이 뜨는가
- **다음 주** — 3주차는 이 파일에 서비스를 하나 더 붙인다. 새로 붙일 것에도 같은 규칙을 쓸 것인가
- **팀** — 지금은 혼자다. 여럿이 같은 파일을 쓰면 무엇이 달라지는가

## 채점하지 않는 것

- **어느 쪽을 골랐는지 보지 않는다.** 둘 다 실무에서 쓰인다 — 고정하는 곳이 많지만, 매일 도는 개발 환경에서는 안 붙이는 쪽이 나을 때도 있다
- 검수는 **§4 「무엇을 포기했는가」가 채워져 있는가**까지다

> **고른 것만 적힌 기록은 결정 기록이 아니라 현황표다.**
> 왜 그것이 아니었는지가 없으면, 다음 사람은 같은 검토를 처음부터 다시 한다.

---

## 한 장을 더 쓸 여유가 있으면

오늘 P3 에서 판단한 것이 하나 더 있다.

> **실습실 PC 는 내 것이 아니다.** 오늘 만든 개인키가 이 PC 에 남는데, 그것을 어떻게 할 것인가 — 두고 갈 것인가, 지우고 갈 것인가, 지운다면 다음 주에 무엇을 다시 해야 하는가.

**같은 네 칸으로 한 장 더 쓴다.** 다만 **문서는 3장을 넘기지 않는다** — 이것을 쓰면 다른 하나는 버린다.
